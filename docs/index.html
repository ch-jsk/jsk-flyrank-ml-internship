Which pages should be reviewed first when CTR underperforms?

Evaluating a client-held-out machine-learning ranking approach for prioritizing SEO pages for human review.

FlyRank ML Internship Capstone · Evaluation of development and temporal test results

01 · Abstract

Abstract

This study investigates whether a machine-learning ranking model can help prioritize SEO pages for human review when click-through rate (CTR) underperforms a position-tier reference. The task uses March features to rank pages against an April-derived reference label, with a separate June outcome evaluation intended to test temporal performance. A Random Forest model is compared with a simple baseline ranking using the same evaluation split and precision-at-10, lift, recall, ranking metrics, and CTR shortfall. On the June temporal evaluation, the model achieved precision-at-10 of 82.55%, compared with 80.65% for the baseline, a gain of 1.90 percentage points. These results support further testing of ranking-assisted review, but do not establish causation, production readiness, or generalization to unseen clients beyond the evaluated data.

02 · Introduction

Introduction and problem statement

SEO teams may have many pages to inspect but limited time for manual diagnosis. A useful prioritization system should help reviewers decide which pages to examine first, rather than claim to determine the cause of a page's performance.

This project evaluates a ranking task: identify pages whose observed CTR is below a frozen reference median for their position tier. The model's intended use is to order candidates for review. It does not predict Google's algorithm, prove that a page needs a particular change, or establish that changing content will improve performance.

Research question. Does a Random Forest ranking approach improve the quality of the first ten pages selected for review compared with a simple baseline, including on a later temporal evaluation?
03 · Data

Data and target definition

The supplied project materials describe data spanning January 27, 2025, through June 30, 2026. The reported March feature partition contains approximately 9.84 million rows; the April and May partitions contain approximately 11.7 million rows each. The evaluated modelling datasets are smaller page-level feature/label tables, not the raw partition counts.

Target and evaluation windows

  • Development evaluation: March features and an April outcome label, using a client-held-out split.
  • Temporal evaluation: March features and June outcomes, evaluated on eight held-out clients.
  • Positive label: observed CTR below the frozen April reference median for the relevant feature-month position tier.
  • Position tiers: 11–20, 21–50, 4–10, and top 3. Pages at positions 51 and beyond were excluded because the reference median was zero.

The nine reported model inputs are log impressions, CTR percentage, weighted position, Search Console days available, search volume, word count, March position tier, content type, and main intent.

Data counts, label rules, and feature descriptions are based on the recorded project results and supplied project documentation. Raw partition sizes should not be interpreted as the number of independent training examples.

04 · Methodology

Model and comparison design

The reported model is a Random Forest classifier with 200 trees, minimum leaf size 10, balanced class weights, and random seed 42. Numeric features use median imputation; categorical features use most-frequent imputation followed by one-hot encoding.

Baseline and metrics

The model is compared with a simple baseline ranking on the same respective evaluation set. Precision-at-10 (P@10) measures the fraction of the first ten ranked pages that have the positive label. Lift compares that precision with the positive-label prevalence; recall-at-10 measures the fraction of all positive examples captured in the first ten. The report also records ROC AUC, average precision, and mean positive CTR shortfall among the top ten.

Split strategy

The development evaluation reports 29 training clients and 8 test clients. The June temporal evaluation reports 21,548 page-level examples across eight held-out clients. A client-held-out split reduces direct overlap of clients between training and testing, while the later outcome window provides a temporal check.

Interpretation rule. All reported model associations and feature importances are descriptive. They do not show that a feature causes CTR underperformance or that acting on a ranking will improve SEO outcomes.

Feature importance

The recorded Random Forest feature-importance results assign the largest importance to March CTR (0.5746), followed by log impressions (0.1567), weighted position (0.0957), word count (0.0742), search volume (0.0331), and Search Console availability (0.0238). These are model-specific importance scores, not causal effects. In particular, a high importance for CTR may partly reflect the relationship between the input and the constructed outcome label.

06 · Limitations

Limitations and honest framing

  • Ranking is not intervention evidence. The study evaluates identification and ordering of labelled examples; it does not test whether changes to those pages improve outcomes.
  • Restricted label definition. The outcome depends on a frozen position-tier median. Excluding positions 51 and beyond limits what can be concluded about those pages.
  • Top-ten sensitivity. Precision-at-10 is based on a very small shortlist. Small ranking changes can move the metric materially.
  • Tier heterogeneity. The model does not outperform the baseline in every June position tier.
  • Generalization is uncertain. Eight held-out clients and one reported temporal evaluation do not establish performance across all clients, industries, or future periods.
  • Reproducibility needs verification. The repository contains a notebook and development record, but this report does not independently verify that a clean runtime can rebuild the sealed evaluation frame and reproduce every reported metric from committed code and inputs.
  • Importance is not causality. Feature-importance values should not be interpreted as evidence that modifying a feature will change CTR.
07 · Recommendations

Ranked recommendations

  1. Use the ranking as a reviewer-assistance shortlist, not an automated decision. Require a human to inspect the underlying page and context before recommending changes.
  2. Run further time-based evaluations. Repeat the evaluation on additional later periods and held-out clients before relying on the observed improvement.
  3. Compare approaches separately by position tier. The June results differ across tiers. A hybrid strategy that keeps the baseline for top-3 and 4–10 pages while testing the model for positions 11–50 is a hypothesis for a future experiment, not a validated recommendation.
  4. Make the pipeline reproducible. Commit the exact evaluation-frame build procedure, metric computation, environment details, and aggregate outputs, then verify the results from a clean runtime.
  5. Measure downstream usefulness. In a future controlled evaluation, measure reviewer agreement, time saved, actionability, and subsequent outcomes without implying causation from ranking metrics alone.
